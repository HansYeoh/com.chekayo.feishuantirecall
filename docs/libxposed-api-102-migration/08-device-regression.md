# 阶段 7：真机回归测试

## 前置条件

- 本机静态验证已通过。
- APK 已签名并安装到测试设备。
- 测试设备使用支持 modern API 102 的框架。
- 目标应用已在框架作用域中启用。
- 涉及真实账号、消息发送、撤回测试时，由用户本人操作测试小号；不要自动操作工作账号。

## 1. 框架加载测试

| 编号 | 测试 | 预期 |
|---|---|---|
| F01 | 模块安装 | 模块能被 modern 框架识别 |
| F02 | 作用域 | 国内版 / 国际版包名可选 |
| F03 | 重启目标应用 | `onModuleLoaded` 和 `onPackageReady` 日志出现 |
| F04 | 重启多次 | 不出现重复 hook 或重复 receiver |
| F05 | 模块自身设置页 | LauncherActivity 正常打开，不依赖 legacy API |
| F06 | 老框架设备 | 模块不加载属于预期，不作为回归失败 |

## 2. 进程覆盖测试

至少确认：

- 飞书主进程。
- 后台通知 / websocket 进程。
- 设置页所在进程。
- 资料页所在进程。
- 国际版 Lark 对应进程（如果设备安装）。

每个进程记录：

```text
process name
package name
ClassLoader identity
installed hook count
native started
config bridge bound
```

## 4. Native 回归

重点检查：

- `libantirecall.so` 能从模块 APK 解出。
- `libresign.so` 能从模块 APK 解出。
- `System.load()` 成功。
- sqlite hook 安装日志正常。
- native maintain 线程正常。
- native 数据目录仍按目标包和账号隔离。
- 没有因为 API 102 生命周期改变而提前加载或重复加载 native。

## 5. Hot reload 回归

第一版只验证安全门控：

1. 在未启动 native 的 Java-only 场景触发 reload。
2. 确认不会重复注册 hook。
3. 在主进程 native 已启动后触发 reload。
4. 确认日志明确写出拒绝原因。
5. 确认目标进程不崩溃。
6. 确认旧 hook 没有和新 hook 重复叠加。

不要把“框架发起了 reload 请求”误判为“模块已完整热重载”。

## 6. 日志采集规范

日志中不得包含：

- 真实聊天正文。
- 真实手机号、邮箱、user ID、tenant ID。
- 真实账号目录中的导出文件。
- 目标 APK 或反编译产物。

PR 只提交脱敏后的：

- 时间线。
- hook 安装结果。
- 错误类型。
- 包名和进程名。
- 飞书版本和 Android 版本。

## 阶段出口

- 国内版目标功能通过。
- 国际版至少完成加载和核心功能验证，若没有安装则记录未测试。
- 多进程没有重复注册和崩溃。
- native loader 和配置桥正常。
- hot reload 的安全拒绝逻辑正常。
- 所有失败项都有复现步骤和日志摘要。
